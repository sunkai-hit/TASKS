# Quick Start

## 在聊天里新增任务

推荐直接使用自然语言：

```
加入 TASKS：
项目：ibms-smart-park
优先级：P0
任务：完成园区 LOD → 楼宇 BIM → 楼层 → 专业系统 → 单设备的交互链路。
要求：
1. 优先解决模型解析慢；
2. 每完成一个阶段提交一次 GitHub；
3. 不需要逐项问我；
4. 只有涉及业务方向选择时再等待我确认。
```

也可以一句话：

```
加入 TASKS，P1：把 Edge-Gateway 的设备配置页面按现有通用开发框架样式重构并提交。
```

AI 应自动：
1. 生成任务 ID；
2. 推断目标仓库；
3. 生成 acceptance_criteria；
4. 写入 queue/tasks.json；
5. 刷新 TASKS.md；
6. 等待下次自动唤起或在当前会话立即执行。

## 查看

说：

```
查看 TASKS
```

应返回：
- 正在执行；
- Ready；
- Waiting User；
- Blocked；
- 最近完成。

## 调整优先级

```
把 TASK-20260924-001 调成 P0
```

## 暂停 / 恢复

```
暂停 TASK-20260924-001
继续 TASK-20260924-001
```

## 取消

```
取消 TASK-20260924-001
```

取消使用 skipped，而不是物理删除，以保留历史。

## 等待我确认

当任务进入 waiting_user 时，用户给出决定后可说：

```
TASK-20260924-001：采用方案 B，继续。
```

AI 应把该决定写入 checkpoint.summary / notes，清除 user_input_needed，并将任务恢复为 ready 或 in_progress。

## 推荐任务粒度

一个任务最好是 30 分钟到数小时的“可独立验收工作包”，内部再通过 checkpoint 分阶段推进。

不建议把“完成整个某某大型系统”写成一个完全不可验收的大任务；可以拆成 5～20 个有依赖关系的任务。
